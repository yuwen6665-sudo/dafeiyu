## 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| **DSH** | 思考、调工具、记忆与情绪的底层能力 | 不直接接触 QQ / 渲染 |
| **qq-bridge** | 把 QQ 消息变成 DSH 的 prompt；注入人格卡；限流；主动搭话 | 不生成语音、不渲染 |
| **SnowLuma** | QQNT 注入 → OneBot v11 协议 | 不理解语义 |
| **yuyaya** | 数字人渲染、情绪惯性、口型、SSE 推流 | 不做 QQ |
| **桌面挂件** | 透明窗口、层级控制、动画 | 不直接调模型 |
| **火山 TTS** | 声音复刻 + 合成 | 不理解上下文 |

## 三条数据流

### 1. QQ 消息

```
QQ → SnowLuma(WS) → qq-bridge → DSH(session/prompt)
                                   ↓ 流式回复
                              qq-bridge → OneBot HTTP → QQ
                                   ↓ 可选
                              voice-sidecar → 火山 TTS → 语音条
```

### 2. 房间对话

```
用户输入 → /api/chat → 大脑（system = 人格卡文件）
        → 流式文本 → SSE /api/events
        → 前端 SpeechPlayer：逐句 → /api/tts → 音频
        → 字幕按 audio.currentTime / duration 推进
        → 口型按 AnalyserNode 音量推进
```

### 3. 桌面挂件

```
pet.html → 播放透明 WebM（逐帧画到 canvas）
        → 每 120ms 上报 pet-bounds.json
        → watcher.exe（30ms 轮询）：
              前台是桌面？ → SetWindowPos(HWND_TOP)
              鼠标在她身上？ → 去掉 WS_EX_TRANSPARENT
              否则 → HWND_BOTTOM + 点击穿透
```

## 端口约定

| 端口 | 服务 | 备注 |
|---|---|---|
| 3000 / 3001 | SnowLuma OneBot HTTP / WS | QQ 登录后才有 |
| 3100 | qq-bridge 控制台 | 有 token 保护 |
| 5099 | SnowLuma WebUI | |
| 8848 | yuyaya（房间 + 桌宠 + TTS） | |
| 50k–65k | DSH | **每次启动会变**，watchdog 负责同步 |

## 为什么这么拆

1. **人格只有一份**：QQ 和房间都用 `persona/于笙.md`，不各写一份
2. **渲染和大脑解耦**：yuyaya 的设计就是这样，换模型/换 agent 都不用动形象
3. **通道可替换**：QQ 走 OneBot，手机端将来走 UI 自动化，都只是"换个通道"
4. **钱的边界清晰**：TTS 在 yuyaya 侧（有缓存），模型在 DSH 侧（有预算）
