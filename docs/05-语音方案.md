# 语音方案

## 为什么用"声音复刻"

预设音色听着"不是她"。用自己的一段录音训练一个音色，她说出来的每句话才有"人"的感觉。

实现：火山引擎 **豆包语音 → 声音复刻 2.0**。

## 一、复刻（一次性）

### 录音要求

| 项 | 要求 |
|---|---|
| 时长 | 30–60 秒（10–30 秒也能训，但细节少） |
| 内容 | 正常说话的连续语句，不要念稿感 |
| 环境 | 无背景音乐、无第二人声、无强混响 |
| 格式 | m4a / wav / mp3 均可 |
| 电平 | mean ≈ −26 dB、peak ≤ −6 dB（别削波） |

拿到录音后裁一段干净的：

```powershell
ffmpeg -i raw.m4a -ss 60 -t 60 -ac 1 -ar 24000 -c:a pcm_s16le ref-60s.wav
```

> 如果平台限制 10–30 秒，用更短的片段；但**参考音频里有多少情绪，合成出来就有多少**。

### 训练

控制台 → 声音复刻 → 上传 → 选效果（ICL 2.0 对语气还原更好）→ 训练 → 得到音色 ID `S_xxxxxxxx`。

同一段音频只能训一个音色；想要"融合两个声音"，需要把两段音频拼成一段再训（效果不稳定），
或者分别训练后用不同的 speaker 交替。

## 二、合成（每句话）

### 接口

```
POST https://openspeech.bytedance.com/api/v3/tts/unidirectional
Headers:
  X-Api-App-Key:     AppID
  X-Api-Access-Key:  Access Token
  X-Api-Request-Id:  uuid
  X-Api-Resource-Id: seed-icl-2.0      # 声音复刻 2.0
Body:
  { user:{uid}, req_params:{ text, speaker, audio_params:{ format:"mp3", sample_rate:24000, ... } } }
```

返回是**分块 JSON 行**，每行 `data` 是 base64 音频，拼起来就是 mp3。

### 参数（实测有效）

| 参数 | 范围 | 效果 |
|---|---|---|
| `emotion` | happy / sad / angry / surprised … | 情绪底色 |
| `emotion_scale` | 1–5 | 强度 |
| `speech_rate` | −50 ~ 100 | 语速 |
| `pitch_rate` | −50 ~ 100 | 音高（**对"起伏"影响最大**） |

实测（同一句话，用 F0 标准差衡量起伏）：

| 配置 | F0 均值 | 起伏 std |
|---|---|---|
| 默认 | 194 | 43.6 |
| `pitch_rate=15` | 206 | **48.5** |
| `pitch_rate=15` + 感叹号 | — | 46.5 |
| `emotion=happy(4)` + 感叹号 | 201 | **60.2** |

结论：**升调 + 感叹号** 是提升"起伏"最便宜的两个杠杆。

## 三、把情绪绑到场景

语音侧车按台词判断场景，自动选参数：

| 场景 | 触发 | 参数 |
|---|---|---|
| 撒娇 | 哼/嘛/好不好/想你…（≤22 字） | happy 5，语速 +8，音高 +15，结尾补「！」 |
| 晚安 | 整句「晚安 / 我睡了 / 早点睡」 | happy 2，语速 −4，音高 +10，结尾补「～」 |
| 关心 | 「记得吃饭/喝水/休息」 | happy 3，语速 −2，音高 +8 |
| 开心 | 「哈哈/好耶/太棒了」开头（≤18 字） | happy 4，语速 +6，音高 +12，补「！」 |

其它句子不转语音（避免刷屏 + 省钱），每个会话 90 秒最多一条。

## 四、成本

| 项 | 单价 | 说明 |
|---|---|---|
| 语音合成 2.0 | 2.8 元/万字符 | |
| 声音复刻 2.0 推理 | **3 元/万字符** | 我们用这个 |
| 流式语音识别 | 1 元/小时 | 将来做 ASR 用 |
| 实时语音大模型 | 输入文本 10 元/百万 token；输入音频 80 元/百万 token | 端到端 S2S，最贵 |

一句 15 字 ≈ **0.0045 元**；免费额度 2 万字 ≈ 1300 句。
缓冲：同一句话有 hash 缓存，重播不花钱。

## 五、字幕与口型同步（房间）

问题：原来字幕用"打字机"固定速度（每秒 9 字）推进，和音频时长无关 → 音画不同步。

改法：

```js
// 每句音频拿到 duration 后，按 currentTime / duration 出字
const n = Math.ceil(text.length * (audio.currentTime / duration));
subtitle.textContent = text.slice(0, n);
```

口型则由 `AnalyserNode` 取音量：

```js
const rms = Math.sqrt(sum / buf.length);
avatar.setMouthLevel(Math.min(1, rms * 3.2));   // 自动量化成 4 级口型
```

兜底：浏览器拦截自动播放时，按估算时长（每字 0.22s）推进字幕，至少读得下来。

## 六、还没做的

| 项 | 说明 |
|---|---|
| ASR（按住说话） | 火山流式识别 1 元/小时，接进来即可 |
| 端到端 S2S（能打断） | 火山实时语音大模型；文档确认复刻音色可用于 S2S 1.0/2.0 |
| 唤醒词 | 需要本地离线关键词检测（不花钱），唤醒后再连云端 |
| 空间感 | 她在房间另一头时音量小一点 + 混响 |

## 七、安全

- 凭证**不要写进代码/仓库**，用环境变量
- 服务端缓存放在 `.cache/`，已被 `.gitignore` 忽略
- 合成失败要能降级成"只有字幕"，不能整段哑掉
